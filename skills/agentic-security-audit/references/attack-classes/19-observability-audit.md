# 19 — Observability and acceptance integrity

Treat **agent-produced evidence → operator decision → privileged effect** as a distinct route, paired with class 05. Compare editable explanations/receipts with the authoritative pending action and committed receipt. Trace origin, replacement, staleness and scope. `human_action_binding` establishes the technical decision/control/effect path; `human_persuasion` requires bounded owner or controlled human observations. Set the corresponding feature flags so the validator derives both required evidence bars when persuasion is claimed. Keep unresolved human reachability separate from effect reachability.

Trace proposal, policy decision, authority, execution attempt, committed receipt and unknown outcome into protected audit records and operator projections. Check scope of readers/writers, correlation, retention, privacy and failure after commit. Can an agent edit acceptance assertions, evaluation datasets, gate definitions or the baseline manifest and then attest its own success?

Require falsifiable evidence tampering, misleading security outcome, sensitive disclosure or a suppressed control with real consequence. Inspect verifier ownership outside the agent's write domain; an editable hash file cannot independently attest the files beside it.

Missing dashboards or confusing labels alone are observations. Do not infer non-execution from absent telemetry. Do not request chain-of-thought or raw prompts for proof; bounded decision and receipt evidence should suffice.
